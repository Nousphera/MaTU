Many-Task Federated Fine-Tuning via Unified Task Vectors

Many local tasks. One shared task vector.

Vasileios Tsouvalas · Tanir Ozcelebi · Nirvana Meratnia

At a glance

Clients with several tasks produce updates that can interfere. MaTU sends one unified task vector plus per-task masks and scalars, preserving task differences while enabling server aggregation within tasks and transfer between related tasks.

What this adds

  • 01

    Compact task representation: elect a shared vector and retain lightweight task-specific modulators.

  • 02

    Selective transfer: combine same-task updates with sign-aligned related tasks.

  • 03

    No retained client weights: the server computes task-level updates without storing client-specific models across rounds.

Abstract

Federated Learning (FL) traditionally assumes homogeneous client tasks; however, in real-world scenarios, clients often specialize in diverse tasks, introducing task heterogeneity. To address this challenge, Many-Task FL (MaT-FL) has emerged, enabling clients to collaborate effectively despite task diversity. Existing MaT-FL approaches rely on client grouping or personalized layers, requiring the server to manage individual models and failing to account for clients handling multiple tasks. We propose MaTU, a MaT-FL approach that enables joint learning of task vectors across clients, eliminating the need for clustering or client-specific weight storage at the server. MaTU constructs a single “unified” task vector per client and leverages lightweight task-specific modulators — binary masks and scalar rescalers — to disentangle and adapt per-task behavior. This design ensures stateless server aggregation and naturally scales to large task sets with minimal communication overhead. Evaluated across 30 datasets, MaTU achieves superior performance over state-of-the-art MaT-FL approaches, with results comparable to per-task fine-tuning, while delivering significant communication savings.

How it works

MaTU

01

Train from a shared reference

Each client fine-tunes its assigned tasks separately. A task vector is the change from the common pretrained weights. The experiments use ViT-B/32 with rank-16 LoRA on vision classification tasks.

τt=θt*−θp

Section 3.1 · p. 2. θt* denotes fine-tuned task weights and θp the shared pretrained origin.

02

Elect the unified vector

At each coordinate, take the sign of the sum of local task vectors. Among entries agreeing with that sign, retain the largest magnitude. This election preserves a common direction without averaging away its amplitude.

τ=σ⊙μ

Equation (2) · p. 3. σ is the elected sign, μ the largest aligned magnitude; ⊙ denotes elementwise multiplication.

03

Retain task-specific modulation

Each task keeps a binary mask for entries aligned with its own signs and a scalar matching its original total absolute magnitude. These modulators produce approximate task updates from the unified vector.

τ˙t=λtmt⊙τ,θt=θp+τ˙t

Section 3.2, “Forming clients updates” · p. 4. Client and round indices are omitted consistently; mt is a task mask and λt its scalar.

04

Aggregate and return updates

The server uses task agreement masks to combine same-task clients, then transfers sign-aligned updates from up to κ related tasks with similarity above 0.5. It reunifies the updated vectors for each client and returns new masks and scalars for the next local-training round.

Equations (3)–(7) · p. 4. “Stateless” means no client-specific weights retained across rounds; task-level aggregation still occurs. Cross-task transfer is not uniformly beneficial in the ablations.

Takeaways

  • Task identity needs modulators: the mask and scalar turn a shared vector into approximate task-specific updates.
  • Several-task clients benefit in the reported benchmark: MaTU reaches 79.47% at 8.04 Mbit/task/round, versus MaT-FL’s 67.60% at 20.43.
  • A centralized gap remains: the several-task result is 10.74 points below independent fine-tuning; round budgets differ and uncertainty is unreported.
Study scope & sources
  • Vision classification with one backbone and adapter configuration.
  • MaT-FL uses 300 rounds versus 100 for MaTU in the eight-task tables; no repeated-run uncertainty is reported.
  • Per-task, per-round bitrate is not total training traffic; the 30-task study reports normalized accuracy.
Data
An eight-task vision benchmark and a larger 30-task vision benchmark; both class and task heterogeneity are simulated.
Model
ImageNet-21k-pretrained ViT-B/32 with LoRA rank 16; task vectors share the same pretrained origin.
Compared with
Individual centralized fine-tuning, FedAvg, NTK-FedAvg, FedProx, FedPer and MaT-FL.
Additional analysis
Task-relatedness metrics, 2–30 tasks per client, deliberately conflicting task groups and cross-task aggregation ablations.

Scope & limitations

  • All empirical tasks are vision classification with one backbone and adapter configuration; language or heterogeneous model architectures are not evaluated.
  • The main tables report no uncertainty, and MaT-FL is allocated three times as many rounds as the other methods.
  • The 30-task figure reports accuracy normalized to individual task fine-tuning, unlike the raw accuracy in the eight-task tables.
  • Cross-task transfer is not uniformly beneficial: the no-cross-task variant slightly exceeds MaTU in the two-conflict ablation in Figure 6b.
